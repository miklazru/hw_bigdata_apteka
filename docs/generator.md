# Генератор данных

```bash
./scripts/seed.sh --seed 42                    # базовая загрузка, ~1 мин
./scripts/seed.sh --seed 777 --receipts 500    # догенерация 500 чеков за «сегодня»
```

Код: `scripts/seed.py` (симуляция и загрузка), `scripts/seed_config.py` (география, словари).
Подключение — переменные `SEED_DB_HOST`, `SEED_DB_PORT`, `SEED_DB_USER`, `SEED_DB_PASSWORD`
(по умолчанию `localhost:5432`, `postgres/postgres`).

## Свойства

| требование | как выполнено |
|---|---|
| детерминированность | единственный источник случайности — `random.Random(seed)`; обход только упорядоченных структур (никаких `set`, зависящих от hash). Одинаковые `--seed` и `--as-of` дают побитово одинаковые данные (проверено сравнением отпечатков всех 14 представлений контракта на двух базах, созданных с нуля) |
| идемпотентность | каждый запуск пишет ключ (`base:seed=42:as_of=…`) в `ref.seed_log` каждой базы в той же транзакции, что и данные. Повторный запуск видит ключ и ничего не делает. Плюс `INSERT … ON CONFLICT DO NOTHING` по BK |
| догенерация | `--receipts N` читает **текущее** состояние источников (остатки аптек из WMS, цены из каталога, клиентов с активной картой из CRM — через контракт) и добавляет N продаж за день `--as-of` с дневным списанием на склад. Номера документов — из отдельного диапазона на каждый seed |
| кросс-сервисная целостность | по построению: симулируется движение товара поставщик → РЦ → аптека → покупатель, продаётся только то, что лежит на полке |
| глубина истории | `--as-of` (по умолчанию — сегодня по Москве): 12 полных месяцев до текущего + текущий месяц по вчера; плюс 42 дня «разогрева» склада до первой продажи |

## Модель

Симуляция идёт по дням. Порядок событий внутри дня выбран так, чтобы последовательность
движений в БД (они вставляются в порядке `moved_at`) никогда не уводила остаток в минус:

1. поступления, доступные с сегодняшнего дня;
2. 09:00 — списание просрочки (`writeoff/expired`), только остаток на начало дня;
3. 12:00 — возврат брака поставщику (`return`, ~1.5% партий);
4. приход заказов поставщику → новая **партия** + движение `receipt` в РЦ;
5. заказы поставщикам: `DC-01` по понедельникам (точка заказа 21 день спроса, заказ до 49 дней),
   региональные поставщики в свои РЦ по вторникам (14 / 35 дней); срок поставки 2–6 / 1–4 дня;
6. среда — магистраль `DC-01` → региональные РЦ (`transfer dc→dc`), партии со сроком ≥ 75 дней;
7. развоз РЦ → аптеки по графику аптеки (1–2 раза в неделю), партии со сроком ≥ 45 дней, FEFO;
8. продажи: только из партий на полке со сроком ≥ даты продажи (FEFO), по действующей цене
   (аптека → регион → сеть), рецептурное — с рецептом;
9. 22:30 — редкая порча в аптеке; 23:59 — дневное списание продаж `sale_writeoff` (ADR-0007);
10. закрытие аптеки — остатки возвращаются в РЦ.

Время транзита зависит от маршрута (Москва — часы, Якутск ~4 суток, Сахалин ~2.5 суток
с вероятностью задержки 20%). У каждой аптеки свой часовой пояс, продажи — по местному времени.

## Распределения (бонус «реалистичные данные»)

| признак | распределение | результат на `--seed 42` |
|---|---|---|
| недельная сезонность | множители пн…вс `1.05, 1.00, 1.00, 1.02, 1.12, 0.86, 0.68`; месячная сезонность (зима ×1.15–1.18, лето ×0.85); 1 января ×0.4, новогодние ×0.8 | max/min по дням недели = 1.62 |
| длинный хвост по SKU | популярность по закону Ципфа: вес = 1 / rank^1.15 (ранги перемешаны); цены логнормальные | топ-10% SKU = 81.8% выручки |
| неравномерность по аптекам | «размер» аптеки ~ LogNormal(0, 0.45) × коэффициент крупного города (Москва 1.6, СПб 1.4…); ассортимент 120–600 SKU в зависимости от размера | CV чеков по аптекам = 0.43 |
| покупки без карты | 55% чеков — клиент с картой (выбор с весом «активности» ~ LogNormal(0, 0.9), 85% — из своего региона) | 45.2% без карты |
| возвраты | 2.7% продаж получают возврат через 1–10 дней, одна или все позиции | 2.67% документов |
| чеков в день | Пуассон(λ), λ = база × размер аптеки × день недели × сезон | ~24.6 тыс. продаж за год |
| позиций в чеке | 1 + Пуассон(2.0), не больше 8; количество 1/2/3 упаковки с вероятностями 78/16/6% | ~2.95 позиции на чек |
| оплата | карта 66% / наличные 34%; 25% клиентов с картой частично платят бонусами; 3% крупных чеков — сертификат 500 ₽ + карта | |
| скидка | только по карте: basic 2%, silver 3%, gold 5%, platinum 7% | |
| цены | сеть: новая версия каждые 60–150 дней, ×U(0.97, 1.10); 25% SKU имеют региональные цены (+5…18% на Дальнем Востоке и Севере, +3% в Москве); 60 промо-цен −15% в отдельных аптеках на 2–4 недели | |
| сроки годности | лекарства 2–3 года, 12% — короткий срок 8–11 мес. (дают реальные списания просрочки) | |

## События во времени (для истории и SCD)

* 3 рецептурных препарата переводятся в безрецептурные, 5 SKU переименовываются — настоящими
  `UPDATE`, журнал `catalog.sku_history` пишет триггер; snapshot в старых чеках сохраняет
  прежние значения (X10: расхождение 0.05%).
* Клиенты: повышение уровня лояльности (10%), переезд (2%), перевыпуск карты (8%),
  отзыв и повторная выдача согласия на маркетинг, «забывание» (~1.2%) — CRM обезличивает,
  POS обнуляет ссылки в чеках (ADR-0008).
* Поставщик `SUP-0010` уходит с рынка через полгода (soft delete), его SKU переходят к `SUP-0001`.
* Две аптеки открываются внутри окна, одна закрывается.

Исторические `updated_at` записываются в режиме `SET app.backfill = 'on'` (ADR-0010):
без него триггер ставил бы всем строкам время загрузки.
