# ADR-0003. История цен: SCD2 + EXCLUDE

**Статус:** принято · **Дата:** 2026-10-13

## Контекст
Цена действует в интервале времени и имеет область: сеть / регион / аптека
(узкая приоритетнее). Контракт `v_price` — версии SCD2 с `valid_from`,
`valid_to`, `is_current`. Нужны инварианты I5 (интервалы не пересекаются)
и детерминированный `is_current` (C10, C11; без `now()` во view).

## Рассмотренные варианты
1. **Только текущая цена в `sku` + журнал изменений.** Отвергнут: ответ на
   вопрос «какая цена действовала 14 марта» требует реконструкции из журнала;
   запланированные цены (с будущим `valid_from`) не выразить.
2. **SCD2 без ограничений в БД, непересечение обеспечивает приложение.**
   Отвергнут: «мой скрипт такого не пишет» — не инвариант.
3. **SCD2 + проверка пересечений триггером.** Отвергнут: триггер с
   `SELECT ... WHERE overlaps` подвержен гонкам при параллельной вставке
   без явных блокировок; EXCLUDE решает это индексом.
4. **SCD2 + `EXCLUDE USING gist` + `is_current` как generated-колонка.** Выбран.

## Решение
Таблица `price (sku_id, price_scope, scope_bk, price, currency, valid_from,
valid_to, is_current)`.
`EXCLUDE USING gist (sku_id WITH =, price_scope WITH =, scope_bk WITH =,
tstzrange(valid_from, valid_to, '[)') WITH &&)` (расширение `btree_gist`).
`is_current boolean GENERATED ALWAYS AS (valid_to IS NULL) STORED` — флаг
детерминирован, C10 следует из EXCLUDE (два открытых интервала всегда
пересекаются), C11 выполняется по построению.
Смена цены = `UPDATE` старой версии (`valid_to = t`) + `INSERT` новой с `valid_from = t`.

## Цена решения
* Смена цены — две операции в одной транзакции, а не одна.
* Версия с запланированным окончанием (`valid_to` в будущем) не считается
  текущей, хотя ещё действует; «действующую на момент t» цену ищем по
  интервалу, а не по `is_current`.
* GiST-индекс тяжелее B-tree на вставку.
* Генератор обязан покрывать цену `chain` по каждому SKU на всю глубину
  истории без дыр — иначе X08.
