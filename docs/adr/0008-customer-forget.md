# ADR-0008. «Забывание» клиента: PII отдельно, POS обнуляет ссылки

**Статус:** принято · **Дата:** 2026-10-13

## Контекст
Физически удалять клиента нельзя (история продаж), но по его запросу он обязан
исчезнуть из аналитики, а контакты — быть обезличены. Контракт исключает
удалённых из `v_customer`. При этом X04 требует, чтобы **каждый** `customer_bk`
из `v_receipt` нашёлся в `v_customer` (ноль сирот).

## Рассмотренные варианты
1. **Удалять (soft delete) только клиентов без покупок.** Проходит X04.
   Отвергнут: подгонка данных под проверку; в жизни забыть себя просят как раз
   реальные покупатели.
2. **Оставлять «забытого» клиента в `v_customer` обезличенным.** Отвергнут:
   противоречит контракту и требованию исчезнуть из аналитики — его покупки
   по-прежнему собираются в профиль.
3. **PII в отдельной таблице с автоматическим обезличиванием + процесс
   забывания затрагивает POS: ссылки на клиента в чеках обнуляются.** Выбран.

## Решение
* CRM: ФИО, телефон, email — в `customer_pii` (1:1). Триггер на установку
  `customer.deleted_at` обнуляет PII и ставит `anonymized_at`, отзывает активные
  согласия и закрывает карты. Восстановить забытого клиента нельзя (триггер).
  Пользователь `checker` к `customer_pii` доступа не имеет.
* POS: по событию «клиент забыт» `receipt.customer_bk` его чеков → NULL;
  чеки становятся анонимными покупками. Генератор имитирует оба шага.

## Цена решения
* Старые чеки меняются (`updated_at` растёт) — DWH перечитает их в инкременте,
  а в детальном слое связь чек — клиент исчезает задним числом.
* Процесс распределён по двум системам без транзакции: между шагами возможно
  окно, когда в POS есть ссылка на уже удалённого клиента.
* Историю покупок забытого клиента восстановить нельзя — это и есть цель.
