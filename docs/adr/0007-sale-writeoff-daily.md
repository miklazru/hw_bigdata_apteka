# ADR-0007. Продажи списываются со склада дневным агрегатом

**Статус:** принято · **Дата:** 2026-10-13

## Контекст
POS и WMS — разные системы. Проданный товар должен уменьшить остаток аптеки
в WMS (тип движения `sale_writeoff`, `dst_type = 'customer'`). Вопрос — с какой
гранулярностью POS передаёт продажи на склад.

## Рассмотренные варианты
1. **Движение на каждую позицию чека (1:1).** Остаток в WMS в реальном
   времени, прямая трассируемость движение ↔ чек. Отвергнут:
   * один и тот же факт продажи живёт в двух источниках — риск задвоить
     продажи в DWH;
   * каждая продажа требует немедленной синхронизации с WMS: при его
     недоступности касса либо встаёт, либо нужна очередь сообщений;
   * так реальные аптечные системы не работают.
2. **Дневной агрегат: одно движение на (аптека, партия, день).** Выбран.
   Аналог — документ «Отчёт о розничных продажах» в учётных системах:
   формируется по закрытию смены и списывает проданное одним документом.

## Решение
Роли разведены: POS — финансовый факт продажи (кто, что, по какой цене, чем
оплачено), WMS — физический факт ухода товара с полки. Детальные продажи DWH
берёт только из POS; `sale_writeoff` используется только для остатков.
`moved_at` = конец локального дня аптеки, `dispatched_at` = NULL.

## Цена решения
* Внутри дня остаток в WMS устаревший — склад узнаёт о продажах вечером.
* По движению в WMS нельзя найти конкретный чек. Для отзыва партии это
  не нужно: `batch_bk` есть в каждой позиции чека в POS.
* При минимальных объёмах (< 1 чека на аптеку в день) агрегат почти не сжимает
  данные — решение архитектурное, не про объём.
