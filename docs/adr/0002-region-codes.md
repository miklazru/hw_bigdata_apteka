# ADR-0002. Коды регионов ISO 3166-2 и локальные справочники

**Статус:** принято · **Дата:** 2026-10-13

## Контекст
Регион встречается в трёх сервисах: регион аптеки (POS), область действия цены
(Catalog, `scope_bk`), регион клиента (CRM). Проверка X08 сопоставляет регион
аптеки с `scope_bk` региональной цены **строковым равенством** между разными
базами. Общей базы-справочника нет и быть не может (FK между сервисами запрещены).

## Рассмотренные варианты
1. **Название региона строкой** («Москва»). Отвергнут: «Москва», «г. Москва»,
   «МОСКВА» не склеятся ни в X08, ни в DWH.
2. **Отдельный сервис-справочник регионов, на который все ссылаются.** Отвергнут:
   это пятая система, а по условию источников четыре; FK к ней всё равно
   невозможен.
3. **Код из внешнего стандарта ISO 3166-2:RU + локальная копия справочника
   в каждой базе.** Выбран.

## Решение
Коды вида `RU-MOW`, `RU-SPE`, `RU-TA`. В каждой из четырёх баз — таблица
`region (region_code PK, region_name)` с одинаковым содержимым; внутри базы
на неё есть честные FK (в Catalog — через generated-колонку `region_code`
из `scope_bk`). Перечень регионов — [geography.md](../geography.md).

## Цена решения
* Четыре копии справочника нужно держать синхронными (у нас — одна миграция-сид
  на все базы). Рассинхрон проявится как сирота в X08 или в DWH.
* Часть новых субъектов РФ в ISO 3166-2 не представлена — при расширении сети
  понадобятся собственные коды.
